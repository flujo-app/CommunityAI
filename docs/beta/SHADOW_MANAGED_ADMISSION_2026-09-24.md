# Shadow-credit admission at the managed API seam

`ShadowMeteredManagedClient` is an explicit wrapper for synthetic `test/*` managed-vLLM profiles. It is **not** registered by the node CLI or enabled on ordinary inference routes. The standalone script `scripts/check_shadow_managed_api.py` registers it with a temporary model manager and exercises the actual FastAPI completion endpoint against a fake loopback backend. No money, external account, real vLLM process, model or GPU is involved.

The API-key store identifies an authenticated caller by its stable nonsecret key ID. `RequestContext` carries that ID plus one request and attempt ID. The managed backend uses the same attempt ID. Before contacting the backend, the wrapper reserves a durable test-unit quote for the synthetic model/profile, bounded context/output, fixed fixture rate and maximum spend. A completed response writes a content-free, **untrusted** receipt with the accepted backend usage. The full quote remains held pending a separate validation decision. An incomplete or failed backend response writes no receipt and releases its hold. Revoked or unfunded keys cannot start work.

SQLite schema v4 saves canonical receipt terms so a separate validator can retrieve pending claims after restart; the audit checks each new receipt's digest and stored columns. Older receipts without this new field remain valid but require manual review if pending. Prompt and completion text, backend key and bearer key are not written to the ledger. The fixture receipt's evidence hash binds metadata and self-reported usage; it does **not** prove useful work. No automatic approval, provider earning, cash conversion, payout or buyer charge occurs in this wrapper. The standalone script deliberately rejects its claims and refunds the test holds.

The script passed on the repository's offline Python 3.12 environment in about 10 seconds. It covers 401 for missing/revoked keys; nonstreaming and SSE completions; an unfunded key and exhausted balance before backend contact; durable pending receipts across restart; failure refund; independent rejection/refund; and a balanced ledger audit. Existing `scripts/check_shadow_credits.py` passed in under a second, and the focused key/request deadline suite passed 31 tests in 11.33 seconds. No broad CI or long model run was used.

This is a local test-unit integration checkpoint. Before paid activation, the remaining work includes globally authenticated buyer identity, independent provider/work validation, authoritative usage, recovery and replay policy, actual pricing/funding, qualified model and hardware routes, and the approved payment and jurisdiction gates in `docs/BETA_ROADMAP.MD`. The test-unit fixture cannot be presented as a live marketplace.
